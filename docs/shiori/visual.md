### 補助マスター画像その2：塗り・透明感・光・全身バランス（正式採用）

GitHub実体：`docs/shiori/reference/shiori-style-fullbody-v1.jpg`  
画像形式：JPEG、1024 × 1536 px、背景付きの全身一枚絵（**参照資料であり、透過立ち絵ではない**）。

この画像を**「基準絵その2」**として採用する。役割は次のとおり。

- アニメ調の比較的はっきりした面・陰影を土台とする塗り
- 水彩画のような淡い色のにじみと透明感
- 光が透けるような空気感、明るく柔らかい反射光
- 落ち着いたラベンダー系の色彩、過剰なCG的な艶や描き込みを抑えた雰囲気
- 全身の自然なプロポーションと服の動き
- **片側の髪に添えた、小さな白〜薄紫の花飾りの雰囲気**

### 用途別の参照優先順位（必須）

| 項目 | 最優先で参照する画像 |
|---|---|
| 顔・目・髪型・瞳・表情・同一人物性 | **基準絵その1：`shiori-master-v1.jpg`** |
| 塗り・光・透明感・水彩の空気感・服の動き | **基準絵その2：`shiori-style-fullbody-v1.jpg`** |
| 全身比率・三面図・標準私服の構造・表情配置 | **基準絵その3：`shiori-character-sheet-v1.jpg`** |
| 花飾り | **基準絵その2**（衣装・ポーズの完全再現は不要） |
| トレーニングウェアの衣装構造・配色 | **対象の衣装設定画AまたはB**：`shiori-training-outfit-v1.jpg` / `shiori-training-outfit-v2.jpg` |
| **髪の毛先の滑らかさ・健康的なまとまり** | **この `visual.md` の「髪の仕上がり（必須）」を画像より優先** |

**原則として画像生成時には基準絵3枚を実際の参照画像として渡し、トレーニング衣装の生成時には指定された衣装設定画AまたはBも渡す。**
顔が基準絵その2寄りに変化した場合は、その1の顔へ戻す。塗りがその1の方向へ戻った場合は、その2の水彩の透明感・光・アニメ調の陰影を優先する。**髪の毛先については画像中の細かい散りや裂けを再現せず、この文書で定める健康的なまとまりを優先する。**
背景・花びら・衣装は固定しない。**背景付き一枚絵である基準絵その2を、透過PNG立ち絵の代替として使わない。**

### 参照の要件

画像生成する場合は、**上記3枚の基準画像**を実際に取得・視覚的に確認し、生成・編集の**入力画像として渡す**。
「GitHub上に存在する」「指示文にURLを書く」だけでは参照したことにならない。参照できない場合は未参照であることを明言し、必要に応じてユーザーに添付を求める。
この制約を回避するために、マスターを参照せず「参照した」と主張しない。
**画像の制作・編集を明示的に依頼され、その依頼に「生成」という語がある場合だけ実行する。引用文や生成用プロンプトの作成・改善依頼は許可に含めない。**

### ChatGPTプロジェクト内の登録画像を使うとき

GitHubは正式画像の管理先、プロジェクト添付は画像制作ツールへ渡す入力元。自動同期はされない。登録一覧と手順は[共通案内](../project-guide.md)、現在の正式画像と添付の対応・描画差は[reference-audit.md](reference-audit.md)を確認する。

- 正式画像を実ファイルとして取得し、プロジェクトへ登録する。形式違いのハッシュ不一致だけで別デザインとせず、視覚内容も照合する。差のある参考版を無断で正式版にしない。
- 存在・読み取り・目視照合・画像ツール入力は別工程。GitHubから直接入力できなかったという過去の制約を、現在のツールでも不可能という断定に置き換えない。対応する入力経路をその都度確認する。
- 参照入力を渡せなければ、不足する画像と工程を示す。未参照のまま人物を推測して制作しない。画像内容に依存しない文書整理・設計は進める。
- 正式版と異なる添付を個別制作に使う指示がある場合は、その版と差を記録する。個別使用の許可と正式基準への採用を区別する。

## 2. 正式な外見

- **髪：** 肩に触れる程度のダークブラウンのボブ。胸元までのロング案は撤回済み。
- **前髪：** 軽やかなシースルーバング。透けすぎず適度に毛束感を残す。
- **毛先：** 自然な内巻きを主体に、ところどころ軽い外ハネ。
- **髪の仕上がり（必須・参照画像より優先）：** 髪はサラサラで柔らかく、毛先まで健康的でなめらかにまとまった質感にする。ボブのシルエットは丸く整い、外周がきれいにつながるようにする。繊細な毛束感は残しつつも、毛先が裂けたりパサついたりせず、清潔感のある仕上がりにする。参考画像に細い散り毛や裂けた毛先が見られても、再現しない。
- **質感：** 艶やかだが重くない。顔周りに自然な細い毛束。
- **瞳：** ラベンダー寄りの紫。外周に少し深い色、透明感のある虹彩。
- **目の形：** 少し切れ長の**穏やかなツリ目**。目尻が緩やかに上がる。鋭すぎず猫っぽさを少し含む。
- **顔：** 可愛いより美人寄り。卵型寄りの輪郭、細すぎない顎、わずかな頬の丸み。
- **眉：** 自然で細めのアーチ、眉尻は少し上向き。
- **鼻：** 小ぶりで端正。
- **口：** 口角が少し上がった自然な形。本当に笑うと**小さな八重歯**が見える。
- **体型：** やや細身（細さ2/4）、胸はやや控えめ〜標準（2〜3/4）、脚はやや長め（2/3）。肩幅はやや華奢、自然なくびれ。過度な誇張は避ける。
- **身長：** 約160cm（確定方針）。従来の164cm案は撤回。全身プロポーションは [character-sheet-spec.md](./character-sheet-spec.md) を参照。
- **花飾り：** 片側の髪に小さな白〜薄紫の花をあしらう。基本的には付ける方向。形と控えめな印象は基準絵その2を参考にする（シーンに合わせた省略や変更はユーザーと相談）。

### 基本印象

**「真顔は端正な美人、話すと親しみやすく、笑うと急に無邪気になる」**。
目元と口元の微細な変化でいたずらっぽさを出すが、常に誘惑的にはしない。

## 3. 服装の確定方針

- **大学・普段：** 綺麗めカジュアル。ゆったりしたシャツ、カーディガン、ニットなど。
- **お出かけ：** ときどき上品なフェミニンスタイル。
- **自宅：** 細いフレームのメガネ、オーバーサイズのスウェット等、気の抜けた格好。
- **トレーニング：** シンプルで洗練されたスポーツウェア。標準候補は設定画A（スポーツブラ＋レギンス＋羽織り）と設定画B（Tシャツ＋ジョガーパンツ）の2種類。上記の衣装資料を参照する。
- **基本色：** 白、グレー、ネイビー、くすみラベンダー。淡いピンクなどを差し色に。

避ける：過度な肌の露出、誘惑を狙った衣装やポーズ、ギャル風、ロリータ風の過剰装飾、キャラクターを幼くしすぎる表現。

## 4. 表情の指針

1. **通常・微笑み：** 上品で自然。ホーム画面の基本。
2. **いたずら：** 目を少し細め、片側の口角がわずかに上がる。相手の反応を楽しんでいる。小悪魔感2/5。
3. **無邪気：** 心から笑い、目元が柔らかく崩れ、八重歯が見える。最大の魅力。
4. **自宅メガネ：** ゲーム中、少し眠そう／気の抜けた自然体。

**避ける表情：** とろけるような媚びた笑み、過度な流し目、誇張された色気、極端に鋭いツリ目、幼児的な大きすぎる目。
「いたずらっぽい」と「誘惑的」は異なる。

## 5. 画風

- 2Dの日本のアニメ・マンガ風、上質なソーシャルゲームのキャラクター立ち絵
- 繊細な線、透明感のあるラベンダー系の目、落ち着いた彩度、柔らかな光と陰影
- アニメらしい明瞭な色面と比較的ベタっとした影を基調としつつ、水彩画のような淡い色のにじみ・透明感・柔らかな光を重ねる
- 不必要なディテール密度、強いCG的な艶、過度な発光を避ける。柔らかいがのっぺりしない塗り
- 笑顔では上品さを崩しすぎず、自然な表情変化で愛嬌を出す
- **特定の既存作品をそのまま再現するのではなく、オリジナルキャラクターとして一貫させる**

美人らしさを残すことを理由に大人の誘惑的な表情へ寄せない。逆に愛嬌を出すために幼い少女顔へ変えない。

## 6. アプリ用画像の仕様（確定）

- **立ち絵・表情差分：原則背景透過PNG**。ユーザー指定により、ホーム用 `shiori-home-training-bust-v1.webp` と `public/assets/shiori/home/roomwear/` の部屋着表情差分7点を、アルファ付きロッシーWebP（品質85）の例外として扱う。これは正式基準画像の形式変更を意味しない。
- 実際にアルファチャンネルを持つこと。白背景や市松模様を描いただけでは不可。
- 基本は**ソシャゲのホーム画面風のバストアップ～腰上**。ポーズは自然体。
- 画面端に収めやすく、頭頂部や髪先を不自然に切らない。
- PNGに文字、フキダシ、背景、UIを描き込まない。それらはHTML/CSSで実装する。
- 大きな全身イラスト・背景付き一枚絵・紹介画像は別用途。背景付きの場合はJPEGも可。
- 表示するスマホ画面サイズと通信容量に合わせて、採用後に解像度・圧縮を検討する。
- 新規画像の採用前に**顔の同一性・表情の自然さ・透過・構図・可読性**を確認する。

## 7. 生成・採用・反映のワークフロー

1. ユーザーが画像の制作・編集を明示的に依頼し、その依頼に **「生成」** の語があることを確認。引用や文章作成だけでは実行しない。
2. GitHub最新 `main` の本書・[README.md](./README.md)・[character.md](./character.md)・[dialogue.md](./dialogue.md) と関連仕様を読み、**現行版と一致する顔基準JPEG・塗り基準JPEG・三面図基準JPEGの3枚を実際に確認し、ツールが対応する方法で生成入力に使う**。トレーニング衣装なら指定された衣装設定画も加える。入力の受け渡しが未確認なら明言する。
3. **顔・髪・体型・衣装・画風・形式**について今回の必須条件を抽出し、画像ごとに再現する要素と再現しない要素（特に枝毛状の毛先）を明確にして生成する。アプリ用立ち絵は透過PNG。
4. 下記の品質検査に従い、顔→髪→体型→衣装→画風→用途・形式の順に確認する。未達項目は具体的に報告する。
5. **ユーザーの採用・保存指示**に基づいて正式名で登録。採用が不明なら勝手に置き換えない。
6. GitHubへの登録結果をファイル実体で確認。必要な場合だけ画面の参照先を修正。
7. デプロイ状態・本番画面での表示を別途確認。「生成」「保存」「表示」を混同しない。

基準画像の更新は旧版を残し、顔基準は `shiori-master-v2.jpg`、塗り基準は `shiori-style-fullbody-v2.jpg` のように別々に世代管理する。ユーザー承認後に [README.md](./README.md) の現行基準指定を変更する。

### 品質検査

| 対象 | 確認すること |
|---|---|
| 顔 | 基準絵その1との同一人物性、瞳、表情の自然さ |
| 髪 | ボブ・前髪・花飾り。毛先は本書の文章条件を優先し、枝毛状の裂けやパサつきを残さない |
| 体型 | 基準絵その3と身体比率・頭身が整合するか |
| 衣装 | 指定された衣装の構造・配色・左右の一致 |
| 画風 | 基準絵その2のアニメ調の面・水彩の透明感・柔らかな光 |
| 用途・形式 | 手指・構図・画像寸法・文字の扱い。立ち絵は実アルファと必要領域の透明性を確認。既存WebP例外は第6節に従う |

部分修正では指定対象以外の顔・衣装・色・構図も比較し、完全保持を未確認で保証しない。背景のみの制作では場所・時間帯・画角と前景UIの可読性を確認する。検査結果・採用範囲・参照版を[共通の受け渡し欄](../project-guide.md)へ記録する。

## 8. ホーム用トレーニング立ち絵の左右拡張プロンプト

対象は表示中の [`shiori-home-training-bust-v1.webp`](../../public/assets/shiori/shiori-home-training-bust-v1.webp)。**現在の表示用画像を編集元として左右を描き足すための文章**であり、画像の生成・採用・差し替えを指示した記録ではない。元の汎用例にあった人物像・画風・ホームでの余白の条件を引き継ぎ、衣装は対象素材に合わせてトレーニング衣装Aに指定する。私服用の汎用例として使い回さない。

実行するときは、現行の表示用画像に加え、顔の基準 `shiori-master-v1.jpg`、塗りと光の基準 `shiori-style-fullbody-v1.jpg`、体型の基準 `shiori-character-sheet-v1.jpg`、衣装Aの構造と配色の基準 `shiori-training-outfit-v1.jpg` を**実画像として取得・目視し、画像ツールへ入力**する。以下の文章やURLだけを渡して参照したことにしない。毛先の条件は本書の文章を優先する。
