### 用途別の参照優先順位（必須）

| 項目 | 最優先で参照する画像 |
|---|---|
| 顔・目・髪型・瞳・表情・同一人物性 | **基準絵その1：`shiori-master-v1.jpg`** |
| 塗り・光・透明感・水彩の空気感・服の動き | **基準絵その2：`shiori-style-fullbody-v1.jpg`** |
| 全身比率・三面図・標準私服の構造・表情配置 | **基準絵その3：`shiori-character-sheet-v1.jpg`** |
| 花飾り | **基準絵その2**（衣装・ポーズの完全再現は不要） |
| トレーニングウェアの衣装構造・配色 | **対象の衣装設定画AまたはB**：`shiori-training-outfit-v1.jpg` / `shiori-training-outfit-v2.jpg` |
| 部屋着の衣装構造・配色・眼鏡・室内履き | **部屋着設定画：`shiori-roomwear-outfit-v1.png`** |
| **髪の毛先の滑らかさ・健康的なまとまり** | **この `visual.md` の「髪の仕上がり（必須）」を画像より優先** |

**原則として画像生成時には基準絵3枚を実際の参照画像として渡し、トレーニング衣装の生成時には指定された衣装設定画AまたはBも渡す。**
顔が基準絵その2寄りに変化した場合は、その1の顔へ戻す。塗りがその1の方向へ戻った場合は、その2の水彩の透明感・光・アニメ調の陰影を優先する。**髪の毛先については画像中の細かい散りや裂けを再現せず、この文書で定める健康的なまとまりを優先する。**
背景・花びら・衣装は固定しない。**背景付き一枚絵である基準絵その2を、透過PNG立ち絵の代替として使わない。**

### 参照の要件

画像生成する場合は、**上記3枚の基準画像**を実際に取得・視覚的に確認し、生成・編集の**入力画像として渡す**。
「GitHub上に存在する」「指示文にURLを書く」だけでは参照したことにならない。参照できない場合は未参照であることを明言し、必要に応じてユーザーに添付を求める。
この制約を回避するために、マスターを参照せず「参照した」と主張しない。
**画像の制作・編集を明示的に依頼され、その依頼に「生成」という語がある場合だけ実行する。引用文や生成用プロンプトの作成・改善依頼は許可に含めない。**

### ChatGPTプロジェクト内の登録画像を使うとき

GitHubは正式画像の管理先、プロジェクト添付は画像制作ツールへ渡す入力元。自動同期はされない。登録一覧と手順は[共通案内](../project-guide.md)、現在の正式画像と添付の対応・描画差は[reference-audit.md](reference-audit.md)を確認する。

- 正式画像を実ファイルとして取得し、プロジェクトへ登録する。形式違いのハッシュ不一致だけで別デザインとせず、視覚内容も照合する。差のある参考版を無断で正式版にしない。
- 存在・読み取り・目視照合・画像ツール入力は別工程。GitHubから直接入力できなかったという過去の制約を、現在のツールでも不可能という断定に置き換えない。対応する入力経路をその都度確認する。
- 参照入力を渡せなければ、不足する画像と工程を示す。未参照のまま人物を推測して制作しない。画像内容に依存しない文書整理・設計は進める。
- 正式版と異なる添付を個別制作に使う指示がある場合は、その版と差を記録する。個別使用の許可と正式基準への採用を区別する。

## 2. 正式な外見

- **髪：** 肩に触れる程度のダークブラウンのボブ。胸元までのロング案は撤回済み。
- **前髪：** 軽やかなシースルーバング。透けすぎず適度に毛束感を残す。
- **毛先：** 自然な内巻きを主体に、ところどころ軽い外ハネ。
- **髪の仕上がり（必須・参照画像より優先）：** 髪はサラサラで柔らかく、毛先まで健康的でなめらかにまとまった質感にする。ボブのシルエットは丸く整い、外周がきれいにつながるようにする。繊細な毛束感は残しつつも、毛先が裂けたりパサついたりせず、清潔感のある仕上がりにする。参考画像に細い散り毛や裂けた毛先が見られても、再現しない。
- **質感：** 艶やかだが重くない。顔周りに自然な細い毛束。
- **瞳：** ラベンダー寄りの紫。外周に少し深い色、透明感のある虹彩。
- **目の形：** 少し切れ長の**穏やかなツリ目**。目尻が緩やかに上がる。鋭すぎず猫っぽさを少し含む。
- **顔：** 可愛いより美人寄り。卵型寄りの輪郭、細すぎない顎、わずかな頬の丸み。
- **眉：** 自然で細めのアーチ、眉尻は少し上向き。
- **鼻：** 小ぶりで端正。
- **口：** 口角が少し上がった自然な形。本当に笑うと**小さな八重歯**が見える。
- **体型：** やや細身（細さ2/4）、胸はやや控えめ〜標準（2〜3/4）、脚はやや長め（2/3）。肩幅はやや華奢、自然なくびれ。過度な誇張は避ける。
- **身長：** 約160cm（確定方針）。従来の164cm案は撤回。全身プロポーションは [character-sheet-spec.md](./character-sheet-spec.md) を参照。
- **花飾り：** 片側の髪に小さな白〜薄紫の花をあしらう。基本的には付ける方向。形と控えめな印象は基準絵その2を参考にする（シーンに合わせた省略や変更はユーザーと相談）。

### 基本印象

**「真顔は端正な美人、話すと親しみやすく、笑うと急に無邪気になる」**。
目元と口元の微細な変化でいたずらっぽさを出すが、常に誘惑的にはしない。

## 3. 服装の確定方針

- **大学・普段：** 綺麗めカジュアル。ゆったりしたシャツ、カーディガン、ニットなど。
- **お出かけ：** ときどき上品なフェミニンスタイル。
- **自宅：** 細いフレームのメガネ、オーバーサイズのスウェット等、気の抜けた格好。具体的な部屋着・眼鏡・室内履きは上記の部屋着設定資料v1を参照する。
- **トレーニング：** シンプルで洗練されたスポーツウェア。標準候補は設定画A（スポーツブラ＋レギンス＋羽織り）と設定画B（Tシャツ＋ジョガーパンツ）の2種類。上記の衣装資料を参照する。
- **基本色：** 白、グレー、ネイビー、くすみラベンダー。淡いピンクなどを差し色に。

避ける：過度な肌の露出、誘惑を狙った衣装やポーズ、ギャル風、ロリータ風の過剰装飾、キャラクターを幼くしすぎる表現。

## 4. 表情の指針

1. **通常・微笑み：** 上品で自然。ホーム画面の基本。
2. **いたずら：** 目を少し細め、片側の口角がわずかに上がる。相手の反応を楽しんでいる。小悪魔感2/5。
3. **無邪気：** 心から笑い、目元が柔らかく崩れ、八重歯が見える。最大の魅力。
4. **自宅メガネ：** ゲーム中、少し眠そう／気の抜けた自然体。

**避ける表情：** とろけるような媚びた笑み、過度な流し目、誇張された色気、極端に鋭いツリ目、幼児的な大きすぎる目。
「いたずらっぽい」と「誘惑的」は異なる。

## 5. 画風

- 2Dの日本のアニメ・マンガ風、上質なソーシャルゲームのキャラクター立ち絵
- 繊細な線、透明感のあるラベンダー系の目、落ち着いた彩度、柔らかな光と陰影
- アニメらしい明瞭な色面と比較的ベタっとした影を基調としつつ、水彩画のような淡い色のにじみ・透明感・柔らかな光を重ねる
- 不必要なディテール密度、強いCG的な艶、過度な発光を避ける。柔らかいがのっぺりしない塗り
- 笑顔では上品さを崩しすぎず、自然な表情変化で愛嬌を出す
- **特定の既存作品をそのまま再現するのではなく、オリジナルキャラクターとして一貫させる**

美人らしさを残すことを理由に大人の誘惑的な表情へ寄せない。逆に愛嬌を出すために幼い少女顔へ変えない。

## 6. アプリ用画像の仕様（確定）

- **立ち絵・表情差分の制作原本：原則実アルファ付き透過PNG**。GitHubへ新規画像を登録する際の転送用コピーは第9節に従い、Base64化より前にロッシーWebP（品質85）へ変換する。現在の表示用WebPは `public/assets/shiori/gim/v1/shiori-home-training-bust-v1.webp` と `public/assets/shiori/home/v1/shiori-home-roomwear-normal-r1.webp`。新しい部屋着7表情（normal/joy/anger/sad/fun/shy/mischievous）は `home/v1/` に登録済み。通常表情のみアプリへ接続し、他6表情の自動切替は未実装。旧版の部屋着7表情は削除済みで再利用しない。既存の正式基準画像・参照資料の形式を遡って変更しない。
- 実際にアルファチャンネルを持つこと。白背景や市松模様を描いただけでは不可。
- **ホーム用の通常立ち絵**はソシャゲのホーム画面風のバストアップ～腰上。ポーズは自然体。現在のホームでの人物の大きさを維持するため、第8節の表示基準と共通プロンプトを用いる。
- 画面端に収めやすく、頭頂部や髪先を不自然に切らない。
- 透過立ち絵に文字、フキダシ、背景、UIを描き込まない。それらはHTML/CSSで実装する。
- 一枚絵・全身イラスト・紹介画像・SD絵は用途に応じて構図、描画範囲、頭身、背景の有無を指定する。ホーム用の縮尺・配置・バストアップ条件は自動適用しない。背景付きの場合はJPEGも可。
- 表示するスマホ画面サイズと通信容量に合わせ、採用後に表示倍率と画質を確認する。GitHub登録用の変換は第9節に従い、原本の寸法・透明余白を自動変更しない。
- 新規画像の採用前に**顔の同一性・表情の自然さ・透過・構図・可読性**を確認する。

### 保存先：場所 → 衣装（確定）

表示用人物画像は `public/assets/shiori/{場所}/{衣装ID}/` に登録する。場所はアプリ画面名ではなく、画像内の栞がいるシチュエーション。ホーム画面でジムの衣装を表示する場合も `gim/` を参照する。

| 場所フォルダ（大文字・小文字を含め固定） | 意味 | 現在の衣装対応 |
|---|---|---|
| `home` | 栞の部屋 | `v1`＝部屋着設定画v1、表情7枚登録済み。`v2`は未登録 |
| `gim` | ジム | `v1`＝トレーニング衣装A、画像あり。`v2`は未登録（衣装Bの登録候補） |
| `town` | 街 | `v1`・`v2`とも衣装未割当・画像未登録 |
| `College` | 大学 | `v1`・`v2`とも衣装未割当・画像未登録 |

```text
public/assets/shiori/
├── home/
│   ├── v1/shiori-home-roomwear-{normal,joy,anger,sad,fun,shy,mischievous}-r1.webp
│   └── v2/
├── gim/
│   ├── v1/shiori-home-training-bust-v1.webp
│   └── v2/
├── town/
│   ├── v1/
│   └── v2/
└── College/
    ├── v1/
    └── v2/
```

- `v1`・`v2`は**場所ごとの別衣装ID**。新旧の改訂番号ではなく、`v2`を追加しても`v1`を廃止・上書きしない。必要なら`v3`以降を追加する。
- 同じ衣装の表情差分・ポーズ差分は同じ衣装フォルダへ置く。新規ファイル名は `shiori-{場所}-{用途}-{表情・ポーズ}-r{改訂番号}.webp` を目安とする。例：`home/v1/shiori-home-standing-smile-r1.webp`。衣装IDと画像改訂を分け、既存ファイル名の末尾`v1`は今回変更しない。
- 場所名は指定どおり `gim` と `College` を使い、`gym`・`college`・背景IDの`city`・`campus`へ自動修正しない。背景ファイルや背景選択IDは従来どおり。
- 空フォルダは`.gitkeep`で保持する。画像が未登録の衣装をアプリの選択肢として有効にしない。保存場所だけで採用・自動配信・背景との衣装連動を確定しない。
- 一枚絵・SD絵も人物素材をここへ登録する場合は場所と衣装を決め、ファイル名で用途を区別する。ホーム用の構図を自動適用しない。
- 顔・塗り・体型・衣装の制作資料は引き続き `docs/shiori/reference/`、背景は `public/assets/backgrounds/` に置く。

現在の表示用素材と接続状況は[実装状況](../implementation-status.md)を参照する。旧試作SVGと旧部屋着7表情は現行ツリーに存在しない。

## 7. 生成・採用・反映のワークフロー

1. ユーザーが画像の制作・編集を明示的に依頼し、その依頼に **「生成」** の語があることを確認。引用や文章作成だけでは実行しない。
2. GitHub最新 `main` の本書・[README.md](./README.md)・[character.md](./character.md)・[dialogue.md](./dialogue.md) と関連仕様を読み、**現行版と一致する顔基準JPEG・塗り基準JPEG・三面図基準JPEGの3枚を実際に確認し、ツールが対応する方法で生成入力に使う**。トレーニング衣装なら指定された衣装設定画も加える。入力の受け渡しが未確認なら明言する。
3. **顔・髪・体型・衣装・画風・形式**について今回の必須条件を抽出し、画像ごとに再現する要素と再現しない要素（特に枝毛状の毛先）を明確にして生成する。アプリ用立ち絵の制作原本は透過PNG。
4. 下記の品質検査に従い、顔→髪→体型→衣装→画風→用途・形式の順に確認する。未達項目は具体的に報告する。
5. **ユーザーの採用・保存指示**に基づき、GitHub登録用画像を第9節の手順でWebP品質85へ変換・検査してから、必要ならそのWebPのバイナリをBase64化し、正式名で登録する。採用が不明なら勝手に置き換えない。
6. GitHubへの登録結果を実ファイルの形式・寸法・透過とともに確認。必要な場合だけ画面の参照先を修正。制作原本と既存の正式基準を保持する。
7. デプロイ状態・本番画面での表示を別途確認。「生成」「保存」「表示」を混同しない。

基準画像の更新は旧版を残し、顔基準は `shiori-master-v2.jpg`、塗り基準は `shiori-style-fullbody-v2.jpg` のように別々に世代管理する。ユーザー承認後に [README.md](./README.md) の現行基準指定を変更する。

## 8. 用途別の制作方針とホーム用プロンプト

### 8.1 適用範囲

| 用途 | 大きさ・構図の決め方 | 共通して守るもの |
|---|---|---|
| ホーム用の通常立ち絵・衣装差分 | 以下の現在のホーム表示を基準に、顔・頭部の見かけの大きさと位置を揃える | 人物設定、正式参照の担当領域、毛先、透過 |
| 同じホーム立ち絵の表情差分 | 基本画像とキャンバス寸法・人物倍率・配置を揃え、切り替え時の大小変化や位置飛びを抑える | 上記と、指定した表情以外の整合性 |
| 一枚絵・イベント絵・全身絵 | 作品ごとに画角・構図・人物の占有率・背景を決める。ホームの大きさや左右余白を強制しない | 人物の同一性、衣装指定、作品に応じた画風 |
| SD絵 | 用途ごとに頭身・デフォルメ・ポーズ・余白を決める。通常立ち絵の頭部寸法や約7頭身の目安を適用しない | 髪型、瞳、花飾り、配色など栞を識別できる特徴 |

依頼の用途が未指定で、文脈からも特定できない場合だけ用途を確認する。SD絵をホームに表示する場合も専用の配置方針を決め、通常立ち絵の縮尺へ自動で合わせない。どの用途でも制作物だけを理由に人物設定を変更しない。

### 8.2 ホームの表示基準（2026-10-16の承認状態を現行基準とする）

**維持するのは、ユーザーが確認した現在のホームでの栞の大きさ。初回調整前に対して95%の状態を基準とし、今後の画像へさらに95%を重ねて縮小しない。** 衣装や表情が変わっても、栞との距離感が急に近く・遠くなったように見せない。

- 確認元main：`6069fd42a619e7b1e419b0b39e90a9fda37bece8`。この時点の[表示用画像](https://github.com/k4n7x2/kintoreapp/blob/6069fd42a619e7b1e419b0b39e90a9fda37bece8/public/assets/shiori/shiori-home-training-bust-v1.webp)（800×1067 px）と[ホーム表示CSS](https://github.com/k4n7x2/kintoreapp/blob/6069fd42a619e7b1e419b0b39e90a9fda37bece8/public/styles.css)を再現可能な基準として残す。
- 基準素材のCSS値は通常 `scale(1.14)`、幅380px以下 `scale(1.159)`、高さ640px以下 `scale(1.064)`、`right: -10px`、右下起点。これは**当該素材の表示値**であり、新素材のピクセル寸法・余白に関係なく同じ数値を当てる規則ではない。
- 大きさは同じ表示領域での**頭頂から顎先までの頭部の高さ**を主に比較し、顔の大きさも目視する。位置は**両目の中心の中点**で比較する。袖の広がりや透明な余白を含む画像全幅だけで倍率を決めない。
- 比較は同じ画面幅・高さ・ブラウザ表示領域で行う。正面〜軽い顔の傾きの通常立ち絵では、頭部の表示高さを基準の±3%以内、目の中点のずれをホーム表示領域の幅・高さそれぞれ±2%以内に収めることを初期の検査目安とする。この許容幅は設計上の目安であり、全素材の測定完了や自動補正の実装済みを意味しない。
- 基準画像は新作に対して**ホームでの大きさ・距離感の参考**として入力する。新作の衣装・表情・ポーズは各依頼に従う。顔・画風・体型の正式な主参照は第1節の3枚を維持する。

透明余白を増やすと、画像枠への一律のフィットでは人物が小さく表示されることがある。**プロンプトだけで表示寸法の一致を保証せず、採用時に基準と並べて表示確認する。** 必要に応じて新素材の表示枠・一様な拡大縮小・位置を調整する。初期の倍率補正は「基準の頭部表示高さ÷新素材の頭部表示高さ」で求め、目の中点を基準位置へ合わせる。縦横別の引き伸ばしや体型の描き変えで合わせない。

引き渡しにはキャンバス寸法、透明余白、人物のアルファ領域、画像内での頭頂・顎先・両目の中点の座標、比較した表示領域の寸法と結果を添える。座標は実画像で確認し、未測定ならその旨を記す。新たな表示補正を実装する際はアプリ開発へ渡す。

- **固定の再現元**：main `5b8d16ce23eab0ec188d69b2d5e33ea5923a4018`（PR #11マージ後）。トレーニングウェアの表示用画像 `public/assets/shiori/gim/v1/shiori-home-training-bust-v1.webp`（800×1067）、部屋着テスト画像 `public/assets/shiori/home/v1/shiori-home-roomwear-test-v1.webp`（941×1672）と、同コミットの `public/styles.css`（`#page-home .character-layer__touch` の衣装別 `--home-character-scale`、`--home-character-origin`、部屋着用 `bottom`）および `public/app.js` の `refreshOutfit()` を照合する。元画像が持つ透明余白・縦横比の差を含む表示を基準とし、画像のピクセルサイズだけを同じにして一致したと扱わない。

### 8.2.2 Home Portrait Standard v1 — 全新規ホーム立ち絵の共通座標規格（2026-10-16）

**正式な制作規則：同じ用途のすべての新規ホーム用立ち絵は、画像を制作する段階から同一のキャンバス・顔アンカー座標・頭部倍率に従う。** 新素材ごとにCSS倍率や表示位置を追加して後から合わせる方式は禁止する。第8.2.1節で承認された2026-10-16のホーム表示（栞の見かけの大きさ・顔の位置・距離感）を維持する。この節の新素材向け基準は、第8.2節の従来の表示誤差目安より優先する。

#### 適用対象・共通キャンバス

- 対象：通常頭身・透過背景のホーム用立ち絵。場所（home／gim／town／College）、衣装ID、表情・通常ホーム向けポーズに関係なく適用する。保存フォルダの「場所」と表示先のホーム画面は別概念。
- 対象外：一枚絵、イベント絵、全身設定画、背景、SD絵。第8.1節に従い、別の用途別規格で制作する。
- **キャンバス規格：941×1672 px。原点は左上 (0,0)、xは右方向、yは下方向。** 現行部屋着7表情のアプリ定義寸法を参考に、新規素材用の統一寸法とする。これは今後の制作規格であり、既存トレーニング画像（800×1067）などのレガシー素材を自動拡大・上書きする指示ではない。PNG原本・WebP登録用コピーとも同寸で、クロップ・リサイズ・自動余白除去は禁止。
- 頭髪・手・衣装の外周から左右画像端まで、各**画像幅10%以上**の完全透明余白を確保する（目標10〜15%）。頭頂にも透過余白を残し、髪・袖・指がキャンバス左右で切れる絵は禁止する。下端はホームのビューポート外へ自然につなぎ、画面途中に画像自体の切断線を露出させず、フェードでごまかさない。
- 画像には文字・吹き出し・背景・UIを描かない。原本は実アルファ付き透過PNG、登録用コピーは第9節のWebP品質85、寸法と透明余白を維持する。
- 新規規格準拠画像はすべてアプリ側の**共通の表示枠・倍率・起点・レスポンシブ規則**を使う。規格準拠画像に衣装・表情単位のCSS個別補正（overrides等）を増やしてはならない。CSSによるタップアニメーションは平常時の基準表示と区別する。

#### 頭部アンカーと合格条件

共通座標テンプレートに次の実測値を一度記録し、**衣装や表情を替えても顔の中心と頭部の大きさを固定する**。髪・袖の横幅やキャンバス枠の大きさだけで人物倍率を評価しない。

| 属性 | 座標の取り方 | 新規素材の検査閾値（設計値） |
|---|---|---|
| 両眼の外形中心の中点 (eye_x, eye_y) | 目頭・目尻などから両目の**配置**の中心を測る。瞳の向きは除外 | 基準座標との差が x/y 各±4px以内 |
| 頭頂 (head_top_y)、顎先 (chin_y) | 花飾りなどを除いた頭髪上端と顎先。頭部高さ = chin_y - head_top_y | 頭部高さは基準の±1.5%以内。頭頂・顎先の位置は各±6px以内 |
| 肩・胴体の基準点 | 左右肩の対応点と胸郭中心。衣装の袖先ではなく身体の位置を見る | 同一ポーズの表情差分は各±6px以内。ポーズ変更は頭部アンカー優先、体型を変形しない |
| アルファ境界 | 実アルファの非透明画素から人物外接領域を測る | 左右とも10%以上の透明余白。左右端に不自然な切れがない |
| キャンバス | 実ファイルの幅・高さ | 941×1672に完全一致。画面側の拡大縮小で誤魔化さない |

- **同じ衣装・ポーズの表情差分**：通常表情のPNG原本を位置・身体の基準として、眉・目・口・頬など必要な顔の範囲だけを変更する。顔輪郭・髪・衣装・姿勢・カメラ位置・頭部倍率を描き直さないことを原則とする。閉眼時は開眼時の眼位置を参照アンカーとする。
- **衣装差分**：服の幅が異なっても、頭部アンカーと倍率は共通。透明余白確保のために人物全体を縮めず、袖や手の構図を安全域へ収める。
- **ポーズ差分**：頭部の位置と大きさを維持した範囲で仕草を変える。大きな首・上半身の移動を要するポーズはホーム通常立ち絵の本規格に無理に押し込まず、別の演出・表示規格として明示する。例外を画像別CSS補正にしない。
- 生成時の文章指示だけで座標一致を保証せず、**完成後に等方拡大縮小・キャンバス内移動で座標を合わせ、再検査する**。縦横別倍率で顔や身体を歪めない。人物の同一性や服が崩れた場合は画像制作から修正する。

#### 基準を数値で確定する手順（初回必須）
