## 1. 対象と参照基準

対象はホーム用通常頭身の近接バストアップ立ち絵（表情差分と衣装差分）。SD・イベント絵・全身設定画・背景は別仕様。

| 用途 | 優先する実画像 |
|---|---|
| 近接構図・頭部の見かけの大きさ | **私服`normal`** |
| 表情の自然な可動域 | **私服`thinking`, `surprised`, `smile`, `playful`** |
| 顔立ち・瞳・髪型・人物同一性 | 正式`shiori-master-v1.jpg` |
| 塗り・光・透明感 | 正式`shiori-style-fullbody-v1.jpg` |
| 体型・自然なバランス | 正式`shiori-character-sheet-v1.jpg` |
| 衣装の構造 | 指定された正式衣装設定・採用済みデザイン |

参照ファイルはGitHubにあっても、そのURLだけで画像制作ツールへ入力されたわけではない。制作のたびに添付実体・対応版と入力結果を確認する。

元のジム`smile-alt1`は旧v2試作の履歴として保存するだけで、今後の**主参照と座標基準には使わない**。

## 2. 制作で揃えるもの／変えてよいもの

**揃える**：キャンバス1086×1448、カメラ距離、近接感、頭部の見かけの大きさ、頭の大まかな向き、人物同一性。同一ポーズの表情差分では髪・花飾り・肩・手・衣装・光のまとまりを維持する（自然な微細差は許容）。

**変えてよい**：眉・まぶた・目の開き・瞳や視線・頬・口・歯／八重歯・表情に伴う顎の自然な変形。意図的な頭の動きは通常の表情差分ではなく別ポーズとして扱う。

表情のために眼や顎の中心が動くのは当然であり、**目頭・目尻の座標、両眼中点、両眼距離、顎先を固定値に強制一致させない**。誤差±6px等の旧閾値によるPASS/FAILは行わない。詳しくは[制作ルール](home-portrait-v2-generation-rules.md)参照。

## 3. 技術要件とQAの責務分離

- 制作原本：1086×1448の実アルファ付き透過PNG。文字・吹き出し・背景は描かない。
- GitHub登録用：別コピーをロッシーWebP品質85へ変換し、アルファ・寸法を維持。
- v1の「左右10%以上完全透明余白」をv2へ適用しない。意図した近接構図の自然な見切れは許容する。
- **自動QA**：[検査器](../../scripts/check_home_portrait_v2.py)で形式／ピクセル寸法／透過／画像がデコードできるかだけをチェック。[単体テスト](../../tests/test_check_home_portrait_v2.py)・[CI](../../.github/workflows/home-portrait-v2-qa.yml)も同じ範囲。
- **目視QA**：私服5枚との並列比較で頭部の大きさ・画角・人物らしさ・衣装・表情・髪・花飾り・手・端の切れ・半透明の縁を確認。
- **アプリQA**：同一端末・同一ビューポート・同一表示CSSで表情切替時の不自然な頭部の跳び、左メニュー・吹き出しとの干渉を確認する。

「TECHNICAL PASS」は**ファイルの技術品質だけ**。見た目やAndroid表示の合格、制作成功、正式採用、公開を意味しない。目視またはAndroid検査が実施できなければ「未確認」と記録する。

## 4. 旧座標監査の扱い

STEP 2〜STEP 5で記録した眼・顎の推定値と計測ログは、過去の試行錯誤を確認できる[監査履歴](home-portrait-v2-step5-review.md)として保持する。**現行仕様の許容座標・修正指示・画像登録ゲートには使用しない**。

機械的な顔アンカーを新たに校正する工程は**今後の必須タスクから外す**。v2の正式採用について必要なのは制作時ルールの合意と実際の目視／Android表示QAであり、座標認証ではない。
