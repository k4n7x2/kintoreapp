> **段階：制作方針として統一を進めるための候補（精密アンカー校正・本採用は未完了）**  
> 2026-10-19、ユーザーの再添付画像 `11621.webp` を実ファイル検査し、従来のv2試作元 `11577.webp` とSHA-256が完全一致することを確認した。  
> 数値の正本候補は [v2 JSON](home-portrait-standard-v2.json)。従来の正式 [v1](home-portrait-standard-v1.json) を無断で廃止せず、アプリの表示CSSや既存画像も変更しない。

## 1. 対象・参照の役割

- **対象**：アプリのホームに重ねる通常頭身の近接バストアップ立ち絵、その衣装・表情差分。背景は透過。ポーズを大きく変えるイベント絵・全身一枚絵・SD絵・背景は対象外。
- **構図・画角・顔位置・頭部倍率の主参照**：ユーザー指定の `11621.webp`（以前の `11577.webp` と同一バイナリ）。同じ画像であることをSHA-256で照合する。
- **人物の同一性・顔・瞳**：正式 `docs/shiori/reference/shiori-master-v1.jpg`。
- **塗り・柔らかな光・水彩の透明感**：正式 `shiori-style-fullbody-v1.jpg`。
- **体型・全身比率**：正式 `shiori-character-sheet-v1.jpg`。
- **衣装**：制作対象の正式衣装資料、またはユーザーが指定・承認した衣装デザイン。構図参照画像のスポーツウェアをすべての衣装に流用しない。
- **毛先**：`visual.md`の健康的で滑らかなまとまりを、参照画像中の散り毛より優先する。

**参照の取り扱い**：GitHubは仕様・ハッシュ・正式画像の管理先で、ChatGPTプロジェクト添付は制作ツールへ渡す入力元。GitHubのリンク・画像ファイルの存在・ChatGPT上の添付表示は、画像制作ツールへの入力成功を意味しない。制作時には該当する添付を実画像として渡せたか別途確認する。取得・入力できなければ生成せず、依存しない仕様整理を進める。画像制作・編集は依頼に「生成」の明示がある場合だけ実行する。

## 3. v2統一キャンバス・顔アンカー

- キャンバス **1086×1448px**、画像左上を `(0,0)`、右がX+、下がY+。制作原本は透過PNG、登録用コピーは透過WebP品質85。**トリミング・余白の付け足し・縦横別の引き伸ばしは禁止**。
- 顔は約30度傾いた近接構図。顔と頭の**見かけの大きさ・向き・カメラ距離**を基準とする。全身を縮小して余白を増やさない。
- 基準画像では意図した上下左右の見切れを許容。顔、目、顎、手指、花飾り、髪の輪郭が不自然に切れるものは別途不合格。下端がアプリ画面内で直線的に露出しないか表示検査する。

## 4. 衣装・表情・ポーズを変える際の固定条件

1. **最初の1枚**：目標の通常表情・衣装・ポーズを基準原本として選定し、実ファイルを保管する。画像の幅・高さだけで一致を宣言せず、座標を注釈する。
2. **同衣装・同ポーズの表情差分**：原本の顔輪郭、髪・花飾り、体型、肩・手、衣装、光の方向、配置を維持。眉・眼・口・頬など必要な領域だけを変える。閉眼時も眼の位置は開眼基準を使う。
3. **衣装差分**：顔のサイズ・両眼中心・頭の傾き・カメラ距離を固定。肩幅や胸郭を服に合わせて不自然に変形させない。服の描画だけ変える。
4. **通常ポーズ差分**：頭部アンカーを優先し、身体の仕草だけ変える。大きな顔の移動を要する構図は本規格とは別の演出用途として扱う。
5. **後処理**：必要なら縦横比を保つ一様な拡大縮小・キャンバス内平行移動で合わせる。顔の変形・見切れの破綻を隠すCSS個別補正を追加しない。

## 5. 暫定QAと正式採用ゲート

**概算アンカーに基づく「提案閾値」（現段階で自動合格扱いにしない）**：両眼中点の各軸±6px、両眼間距離±2%、顎先の各軸±8px。正式閾値は反復注釈・試作画像比較で再決定する。

検査順序：
1. ユーザー指定参照画像の取得・ハッシュ照合、人物基準3枚・対象衣装の参照入力状態の記録。
2. 制作原本PNGの1086×1448・実アルファ・想定した画角・四辺の描画状態を検査。**v1の左右10%ルールは適用しない**。
3. 基準と新作で両眼・顎・肩を直接注釈し、数値差と目視差を両方評価。同ポーズでは顔以外の描画差も確認。
4. 背景透過PNG原本とは別にロッシーWebP品質85を作り、アルファ・寸法・半透明輪郭・明暗背景での白縁と黒縁を検査。
5. v2用の共通表示枠・CSSを検討し、画面幅320/360/393/430px、短い画面高640px以下、吹き出し／左メニューへの干渉、表情切替時の位置飛びを比較。
6. ユーザー採用・GitHub保存・アプリ組み込み・デプロイ・Android実機検証を**別々**に記録。数値未測定・実機未確認は合格にしない。

## 6. v1・既存素材との棲み分け

- `Home Portrait Standard v1`（941×1672）は**現在のGitHub正式仕様として保持**する。本v2は、ユーザー選定の近接構図を今後のホーム立ち絵へ統一するための制作方針案。
- 現行のジム5表情・私服v2試験版5表情は1086×1448、部屋着7表情は941×1672。寸法が一致しても眼位置が一致するとは限らず、既存画像のv2アンカー合格は未確認。
- 既存CSS・素材・本番表示はこの文書作業では**変更しない**。全衣装の表示を同じ構図へ統一するには、まずアンカー校正、代表素材の再検査、v2共通CSSによる実機表示確認を別工程で行う。
- v2本採用時は `visual.md` の新規ホーム制作ルール、使用するJSON、検査スクリプト／CI、アプリの表示経路を**一度に整合**させる。現段階でv1規格への強制変換・削除はしない。

## 7. このプロジェクトでの制作指示の使い方

「ホーム用1086×1448の栞を制作する」という依頼では、**このv2仕様案＋今回の実添付画像＋顔／塗り／体型の正式参照3枚＋指定衣装参照**を優先して構図を設計する。添付ファイルが会話をまたいで参照入力可能かは制作ごとに確認する。

- 規格名称：`home-portrait-v2-trial`
- 元画像の識別子：上記SHA-256（必須）
- キャンバス：1086×1448（必須）
- 眼中点・顎先：暫定候補、実画像で再計測必須
- アプリ内での顔の表示位置は**画像内座標とは別物**。完成後に同一ビューポートで比較しないまま完全一致と主張しない。

**次に必要**：元画像の確実な長期保管／参照入力方法の確認、2回の独立アンカー測定、通常表情のv2基準原本の選定、v2用QA検査・共通CSSの実機試験、明示的な最終採用判断。
