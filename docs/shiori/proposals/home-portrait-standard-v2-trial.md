# Home Portrait Standard v2 — 1086 × 1448 試作仕様（採用前）

## 目的と扱い

ユーザーが2026-10-19の会話で「このサイズと添付画像が理想」と明示した **1086×1448pxのトレーニングウェア立ち絵**を、ホーム用通常頭身立ち絵の**構図・表示サイズ感の試験マスター**として扱う。

**これは試作資料であり、正式規格・人物設定・既存素材・CSSの変更ではない。** 正式な顔と画風の主参照は `docs/shiori/visual.md` 第1節の画像3枚のまま。現行 v1（941×1672、承認済みAndroid画面からの逆算）と別系統で試す。PR #14 の監査改修を黙って置換しない。

- **出典**：会話添付 `11577.webp`。実バイナリ1086×1448、RGBA透過WebP。SHA-256 `47804149850a46b41767c66eeff459260369d3bc6e5ae897d3b2004bff5bbdf1`。
- 添付画像そのものは**GitHubへ登録していない**。この文書と [座標JSON](home-portrait-standard-v2-trial.json) が揃っても、元画像を取得・照合したことの代用にはならない。正式採用前に参照画像を別版としてGitHubの制作資料へ登録し、SHAと描画差を確認する。
- 原本はトレーニング衣装であるが、ポーズや表情の差分で人物を勝手に変更しない。立ち絵の場面や衣装IDは従来どおり場所→衣装フォルダで管理する。

## 余白と画角に関するv1からの変更

この原本はアルファ付きだが、画面の上下左右に非透明画素が実在する（alpha>32：上38px／左38px／右318px／下945px）。**v1の「左右10%以上は完全透明余白」を採用すると、今回の理想画像自体が不合格になる。**

v2試作では、近接バストアップ構図として**意図的な端への接触／見切れを許可する**。ただし、顔・目・顎・手・髪が不自然に切れないことを必須の目視条件とする。キャラクターの下端がホーム画面に露出して不自然な直線を出す場合は表示枠の側で検査する。勝手な透明フェードや不自然な四辺余白の追加で帳尻を合わせない。

## 制作指示テンプレート（画像を制作する依頼時に参照するだけ）

> 基準画像 `11577.webp` と**同一の1086×1448ピクセル**の透明キャンバスで、元画像と同じカメラ距離、顔の位置、両眼間距離、頭部倍率、上半身の占有率を維持してください。両眼中点は概ね(503,402)、顎先は(592,585)を目標にします。髪は上端付近、身体と衣装は原本と同様の近接構図で、意図的な画面外の続き方を尊重します。左右10%の余白は要求しません。表情差分ではポーズ・顔輪郭・髪・衣装を描き直さず、表情パーツだけを変更してください。独立した衣装差分でも顔のサイズと位置を優先してください。顔・画風・衣装詳細はGitHubの正式資料に従い、構図参照のみを本画像から取ってください。

これは**制作時の目標値**であり、画像モデルがピクセル単位で忠実に従うことの保証ではない。出力サイズのネイティブ対応がない場合は無断で別サイズに決定せず、制作段階でサイズ制約を報告し、変形のない後処理計画を提示する。

## 試験的な検品条件（正式ゲートではない）

1. 元画像と同じ1086×1448、背景は実アルファ、PNG原本→ロッシーWebP品質85の別コピーへ変換。勝手な自動トリム、縦横別の画像拡大縮小は禁止。
2. 元画像を使用し、眼・顎のポイントを最低2回独立に注釈して再現性を記録。現段階の候補許容値は眼中点のx/y各±6px、両眼距離±2%、顎先x/y各±8px。ただしアンカーの精密計測完了までは**合格を宣言しない**。
3. 顔の範囲ガイド・肩・髪・衣装・手指の変更を目視検査する。異ポーズまで眼の角度完全一致を強制しない。同一ポーズの表情差分では輪郭の保持を厳格に確認する。
4. 1086×1448はv1（941×1672）と縦横比が異なる。アプリでv1のCSSをそのまま適用して「同じ見え方になる」と仮定しない。新規格画像には共通のv2表示経路を別に設け、Android画面幅320/360/393/430pxと短い画面高で試す。
5. 登録前検査は、画像のメタデータ、実アルファ、SHAとの対応、座標注釈、目視検査、Android表示確認を区別する。画像の一つの検査成功で正式採用を確定しない。
