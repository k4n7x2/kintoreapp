# Home Portrait Standard v1 — 計測・登録前検査

正本は [visual.md §8.2.2](visual.md) と [共通座標JSON](home-portrait-standard-v1.json)。対象は**新たに制作するホーム表示用の通常頭身・透過立ち絵**。既存8枚のWebPはレガシー素材として保持し、無断で移動・差替えしない。一枚絵・SD絵には適用しない。

## 基準データの現状：画面基準の校正完了（2026-10-16）

- **status: calibrated**。承認済みAndroidスクリーンショット（691×1536px）で、部屋着「喜」の顔位置をピクセルグリッド上で計測した。現行CSSの倍率・起点・下端オフセットを逆算し、**共通941×1672キャンバス上の名目座標**として両眼中点 `[449,321]`、頭頂Y `27`、顎先Y `449` に確定した。
- **根拠の種類**：画面上の目・頭頂・顎を人手で測った**スクリーンショット由来**の値。元WebPを直接クリックした実測値ではない。元WebPは画像として目視し、顔と画面の整合を確認したが、直接の画像ピクセル注釈や自動顔検出を実行したとは称しない。画面側の手動注釈はおおむね±2スクリーンpxの不確かさを含む。
- CSS座標モデルで画面に再投影した結果は、目X約0.23px、目Y約0.01px、頭頂約0.37px、顎先約0.21pxの内部計算差だった。**これは逆変換の整合性であり、独立したAndroid実機検査済みという意味ではない。**
- [基準JSON](home-portrait-standard-v1.json)には、画面サイズ・Web表示領域・CSSスナップショット・測定点・投影結果を保存。スクリーンショット本体やAndroid通知は公開GitHubへ保存しない。
- 基準校正の再検算と画像検査の単体テスト：

```bash
python scripts/verify_home_calibration.py
python -m unittest discover -s tests -v
```

- 肩アンカーは**未測定**。同一ポーズの肩座標を検査するには、別途基準画像で座標注釈が必要。`samePoseAsReference: true` はその測定まで合格にならない。既存画像8枚を新規規格へ自動合格させたり、既存CSS・素材を変更したりしない。
- **今後の最終表示確認**：最初の新規格準拠素材を組み込んだ際、承認済みAndroid表示と顔・頭部位置・体格・下端の自然な見切れを比較する。制作上の顔の同一性は別途検査する。

## 新素材の登録前の実行手順

1. 通常ホーム用画像を**941×1672px**の透過PNGで制作する。顔・塗り・体型・衣装は通常の正式参照に従う。
2. 完成した画像上で、eyeCenter（左右の目の外形中心の中点）、headTopY、chinY を計測し、必要なら肩の座標も測る。これらは**画像内の座標**であり、スクリーンショット上の座標を転記しない。
3. 原本の横に画像名＋.anchors.json のサイドカーを置く。例：new-image.png.anchors.json。人間が画像と照合して初めてreviewed: trueにする。

```json
{
  "standard": "home-portrait-v1",
  "reviewed": true,
  "samePoseAsReference": false,
  "anchors": {
    "eyeCenter": [449, 321],
    "headTopY": 27,
    "chinY": 449
  }
}
```

画像ファイル名には用途識別子 `-home-` を含める（例：`shiori-gim-home-normal-r1.webp`）。PR検査が通常ホーム立ち絵とSD絵・一枚絵を区別するための必須の命名規則。

数値は**共通基準を示す形式例**であり、個々の新しい画像を測らずコピーすることは禁止。画像内に実在する顔の座標を注釈した結果だけを登録する。立ち絵の姿勢が参照画像と完全に同じ場合はsamePoseAsReference: trueとしてleftShoulder、rightShoulderも記載する。

4. Pillow を用意して検査する。

```bash
python -m pip install Pillow
python scripts/check_home_portrait.py /path/to/new-image.png
```

5. 必須検査に合格したらWebP品質85の別コピーへ変換し、同じ寸法・透明余白・アンカーを維持したことを再検査してからGitHubへ登録する。GitHub Actionsは**PRで新規に追加するホーム立ち絵**を対象にチェックする。もともとのレガシー画像・一枚絵・SD絵は対象外。顔の同一性、毛先、手指、透過縁、表示画面での見え方は引き続き人間による検査が必要。

### 試行時の注意

基準JSONの校正は完了。--allow-provisional は検査器の**開発診断専用**であり、本採用やGitHub Actionsでは使用しない。新しい画像の寸法・透過・人手レビュー済みのアンカー注釈が欠ければ引き続き不合格となる。

**スクリプトが目の位置を画像から自動検出するわけではない。** 人手による実測・注釈と、自動の寸法／アルファ／透明余白／座標差計算を組み合わせる。顔以外の線画の同一性や下端の自然な見切れについては別途目視する。
