# 朝倉 栞 — キャラクター制作・運用資料

このディレクトリは、筋トレアプリ `kintoreapp` に登場するオリジナルキャラクター **朝倉 栞（あさくら しおり）** の正式仕様を管理する。

## 作業開始時に読む順序（必須）

朝倉栞の画像生成・セリフ作成・キャラクター表示・演出・衣装差分・プロフィール作成など、**キャラクターに関係する作業の前には、GitHubの最新 `main` から以下をすべて読み込む**。

1. [character.md](./character.md) — 人物像・性格・趣味・言動の設定
2. [visual.md](./visual.md) — 顔・画風・基準画像・画像生成／保存仕様
3. [dialogue.md](./dialogue.md) — 口調・会話例・セリフ設計・NG表現
4. [reference/shiori-master-v1.jpg](./reference/shiori-master-v1.jpg) — **基準絵その1：顔・髪型・瞳・表情の最優先基準**
5. [reference/shiori-style-fullbody-v1.jpg](./reference/shiori-style-fullbody-v1.jpg) — **基準絵その2：水彩の透明感・光・アニメ調の塗り・全身バランス・花飾り**
6. [character-sheet-spec.md](./character-sheet-spec.md) — **三面図・身長と体型・私服・喜怒哀楽4表情の制作仕様書**
7. [reference/shiori-character-sheet-v1.jpg](./reference/shiori-character-sheet-v1.jpg) — **基準絵その3：正式採用済みの三面図・標準私服・喜怒哀楽・花飾り・色見本**
8. [reference/shiori-training-outfit-v1.jpg](./reference/shiori-training-outfit-v1.jpg) — **トレーニングウェアA：スポーツブラ・レギンス・羽織りの三面図**
9. [reference/shiori-training-outfit-v2.jpg](./reference/shiori-training-outfit-v2.jpg) — **トレーニングウェアB：スポーツTシャツ・ジョガーパンツの三面図**

これらの内容を省略して過去の会話や短いプロジェクト指示だけからキャラクターを推測しない。詳細を確認できなければ、その旨をユーザーに伝える。

**全身立ち絵・衣装差分・体型や表情を扱う場合は、`character-sheet-spec.md` を必ず参照すること。** 基準絵その3の画像も正式登録済み。作画資料として画像と仕様書の両方を確認する。**トレーニング衣装を制作する際は、該当するウェア設定画AまたはBも実際に参照する。**

## ChatGPTプロジェクト内の基準画像の利用

ChatGPTプロジェクト「筋トレアプリ開発」には、現在以下の5枚の参考画像を登録している。

- `shiori-master-v1.png` — 顔・瞳・表情・同一人物性
- `shiori-style-fullbody-v1.png` — 画風・光・水彩風の透明感
- `shiori-character-sheet-v1.png` — 身体バランス・標準私服
- `shiori-training-outfit-v1.jpg` — トレーニングウェアA
- `shiori-training-outfit-v2.jpg` — トレーニングウェアB

**正式な設定・画像の管理元は常にGitHubの最新 `main` とする。** GitHubの現行基準絵その1〜3は `docs/shiori/reference/` 内の **JPEG**、ChatGPTプロジェクトに登録した対応画像その1〜3は **PNG**。トレーニングウェアA・BはどちらもJPEG。プロジェクト側は制作時に再利用するための複製であり、自動同期されるとは限らない。

作業開始時は最新 `main` の設定文書・基準画像のファイル名と版を確認し、**プロジェクト側の対応画像と画面内容・人物デザインを照合する**。JPEGからPNGへの変換などファイル形式や画像寸法が異なる場合、ファイルのバイト列やGit Blob SHAは一致しなくてよい。同形式・同一バイト列のときに限りハッシュ一致を同一性の補助確認に利用する。版違いや視覚的な内容不一致があれば報告し、古い画像を現行基準として扱わない。

画像制作時は、必要なプロジェクト登録画像を実際に読み込んで視覚的に確認し、**画像生成・編集ツールが対応する方法で参照入力へ渡す**。GitHubで見つけた、プロジェクトに登録されている、画像を閲覧できた、という事実だけでは生成ツールへ渡した証明にならない。ツールが受け付けない入力パラメータを想像して指定したり、画像が似ていることだけから「参照渡し成功」と断定したりしない。

参照入力の受け渡しを確認できない場合は、その状態を明示し、必要に応じてこのチャットへの画像添付を依頼する。**「画像を取得・確認できた」「生成入力に渡せた」「生成された」「正式採用された」「GitHubに登録された」「本番に表示された」は別々に判定する。**

## 設定の優先順位

1. ユーザーの最新の明示的な決定・修正
2. GitHub `main` のこのディレクトリにある確定設定・正式マスター画像
3. 既存アプリの実コード・画像・セリフデータ（**実装状態**の確認に使用）
4. 過去の会話や仮案

**資料は一律の優先順位ではなく、要素ごとに主参照を指定する。** 詳細は以下の「画像生成時の参照優先順位」に従う。原則3枚の基準絵を実際に参照し、トレーニング衣装では対象の衣装設定画も追加する。衣装・ポーズ・背景は、個別指示がない限り固定しない。
「確定」「仮」「未決定」を区別し、仮案を既成事実にしない。

## 画像生成時の参照優先順位（必須）

**複数の参考画像を同じ重みで混ぜないこと。** 各要素には以下の主参照を割り当てる。

| 生成する要素 | 最優先する資料 |
|---|---|
| 顔立ち・目・瞳・表情・同一人物性 | **基準絵その1**：`reference/shiori-master-v1.jpg` |
| アニメ調の塗り・光・水彩の透明感・空気感 | **基準絵その2**：`reference/shiori-style-fullbody-v1.jpg` |
| 身長約160cm・体型・頭身・全身バランス・標準私服 | **基準絵その3**：`reference/shiori-character-sheet-v1.jpg` および `character-sheet-spec.md` |
| トレーニングウェアの形状・構造・配色 | **指定された衣装設定画**：`reference/shiori-training-outfit-v1.jpg`（A）または `reference/shiori-training-outfit-v2.jpg`（B） |
| **髪の毛先の仕上がり・健康的なサラサラ感** | **最新の文章仕様**：`visual.md` の「髪の仕上がり（必須）」 |

**競合時の処理：** 各要素について、当該要素を担当する主参照を優先する。**とくに髪の毛先は、参考画像の描写より最新の `visual.md` の明示的な文章条件を優先する。** 参考画像に散り毛・枝毛状の裂け・パサついた毛先が見えても、それを意図的に引き継がない。サラサラした柔らかな質感は残し、毛先まで健康的でなめらかな、外周のつながったボブに仕上げる。

ユーザーが今回の制作について明示した新しい修正条件は、既存資料の該当箇所より優先する。ただし正式基準の変更が確定した場合は、GitHub側の文書も更新する。

## 画像生成前後の品質管理（必須）

### 生成前

1. GitHubの最新 `main` にある本README・`character.md`・`visual.md`・`dialogue.md` と、今回の用途に必要な仕様書を取得して読む。
2. GitHubの正式基準とプロジェクト登録画像の版・内容を照合し、基準絵その1〜3を実際に確認する。衣装指定がある場合は対象の設定画AまたはBも確認する。
3. **今回の必須条件を「顔・髪・体型・衣装・画風・構図／形式」に分け、優先する参照元とともに整理する。** 文書をただ長く引用するだけで済ませない。
4. 参照画像を生成・編集ツールがサポートする方法で実際に入力へ渡し、再現する要素と**再現しない要素**（例：枝毛状の毛先）を明示する。受け渡しが未確認なら成功と断定せず、その制約を伝える。
5. ユーザーの明示的な「生成」指示がある場合だけ生成を実行する。

### 生成後

1. **顔：** 基準絵その1と同一人物に見えるか。
2. **髪：** ボブの形・前髪・花飾りと、**`visual.md` 指定の滑らかな毛先**を満たすか。枝毛状の裂けや傷んで見える散り毛を残していないか。
3. **体型：** 約160cmの頭身・身体バランスが基準絵その3に沿うか。
4. **衣装：** 指定の標準私服／トレーニングウェアA・Bを正しく再現しているか。
5. **画風：** 基準絵その2のアニメ調の面・水彩の透明感・柔らかな光に沿うか。
6. **用途：** 構図・手足・画像サイズ・文字の扱いは適切か。**アプリ用立ち絵なら実アルファ付きの透過PNGか。**

問題があれば、**どの必須条件が未達か具体的に報告**し、修正対象を絞る。資料を読んだだけで条件を満たしたことにはしない。生成できても、ユーザーが採用する前に勝手に正式素材へ登録・差し替えしない。

## 画像生成の必須ルール

- ユーザーの依頼に **「生成」** が明記されない限り画像生成しない。
- 生成時は**顔基準JPEG・塗り基準JPEG・キャラクターシートJPEGの3枚**を原則実際に確認して参照入力へ渡す。GitHubと同一版のプロジェクト登録画像を利用してよい。URL・ファイル名の記載や閲覧だけで「生成入力に渡した」と扱わない。
- トレーニングウェア画像の生成時は、上記3枚に加えて選んだ**ウェア設定画AまたはB**を衣装の参照資料として使う。2種類は別衣装であり、v2はv1の上書き・廃止を意味しない。顔・体型・塗りはそれぞれ既存の基準絵その1〜3を優先する。
- 参照画像を渡せない場合は制約を説明し、必要に応じて添付を求める。
- **アプリに表示する立ち絵系は背景透過PNG（実アルファチャンネル必須）**。マスター画像などの制作資料はこの制限を受けない。
- 画像生成の成功、GitHubへの登録、アプリへの反映、デプロイ完了をそれぞれ別に確認する。
- 画像が生成されたという理由だけで正式素材にせず、ユーザーの採用判断を尊重する。

## 文書の更新

人物像・画風などの重要な設定変更はユーザーの合意を得てからこのディレクトリに反映する。設定の更新とコードの変更は別作業である。
旧マスター画像は上書きせず、`-v2` などの世代付きファイルとして残し、ここに現行版を明記する。
文章が増えたらこのディレクトリに分割してよいが、本ファイルから必ず辿れるようにする。
